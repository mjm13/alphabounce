## 1. 源码梳理摘要

### 1.1 两份源码是"同一套架构"的现代与原始形态

经对比，EternalTwin 重写版与原版 2007 的 **模块结构几乎 1:1 对应**（见下表）。
因此本次复刻**以 EternalTwin 为主参考**（代码清晰、资产齐全、带设计文档），**以原版作保真对照**（真实机制/平衡/FLA 美术/多语言文本）。

| 维度 | WebGamesArchives（原版 2007） | EternalTwin（现代重写） |
|---|---|---|
| 语言/目标 | Haxe → Flash (SWF) | Haxe → HTML5/JS (PixiJS) |
| 游戏源码 | `client/src/` 72 个 `.hx` | `frontend/src/haxe/` 79 个 `.hx` + `common/` 5 个 |
| 美术资源 | FLA 源 + 编译 SWF + web/img | **4179 张 PNG 精灵帧** + 5 个 woff 字体 |
| 玩法文档 | 无 | 上游附带一份玩家攻略（禁转载，不入库；事实提取见 `docs/reference/alphabounce-facts.md`） |
| 后端 | 无（纯前端） | Node + Redis（账号/排行榜/云存档） |
| 多语言 | `web/xml/{de,en,es,fr}` | `TextDe/En/Es/Fr.hx` |
| 许可证 | CC BY-NC-SA 4.0 | AGPL-3.0 |
| 磁盘 | 48M（sparse） | 63M |

### 1.4 关键事实（出处与逐条引用见 `docs/reference/alphabounce-facts.md`）

- **目标**：找到第 27 颗星球 Earth（随机藏于某星球，需 Sonar 探测地图碎片）。
- **星球**：共 27 颗（26 普通 + Earth 终点）；通关整颗星球解锁其 envelope（飞船/挡板）。
- **增益/减益**：共 **25 种**（字母 A–Z 除 P，每击碎方块掉落对应字母拾取触发）：
  - **Bonus（18）**：Attraction, Barrier, Chaos Field, Extension, Frenzy, Halo, Javelin, Laceration, Multiball, Nebula, Open!!!, Quasar, Regeneration, Sapper, Terraforming, Ultraviolet, Vendetta, Xenox
  - **Malus（7）**：Diminish, Gelato, Indigestion, Kamikaze, Whisky, Yoga, Zealot
- **P-Bonus（7，随飞船不同）**：Pilot, Pogo, Paradox, Pause, Peace, Pyromancer, **Provision**；多数偏负面。
- **球**：多种类型（如 Standard Drilling Ball、Safe Ball），各自攻击力不同；多球时额外球分布左右。
- **导弹**：挡板左右发射，数量有限；Provision（P-Bonus，非拾取道具）可补满至上限；原版浏览器版通关不补、DSi 版补（设计取舍点）。
- **无人机**：随球撞击挡板自动部署，自动攻击场上目标。
- **经济**：Minerals（矿物）为货币；Shop 购买装备与升级。
- **飞船**：共 **28 种** envelope（#01 ESC-STD 初始 + 27 颗星球各奖励一种），每种自带 P-Bonus、
  2~6 个装备槽与隐藏 Defense（护甲）属性。**「3」是舰队槽位数**（可拾取扩到 4），不是飞船总数——
  早期版本此处误记为「3 艘飞船」，P8 范围须按 28 种重算。
- **装备系统**：装备占槽位、提供属性（含 Defense：每点减 1 点伤害，常见 1/2/5/7），是原作策略核心；
  **P0–P12 全部需求均未覆盖**，须新增需求或并入 P8。
- **关卡生成**：**确定性程序生成**（同一随机 seed 每次结果一致，掩盖"非手工设计"痕迹）；支持 2500 万关量级。
- **砖块(conglomerate)**：40+ 种，行为各异（部分敌人会射击、部分不可破、部分特殊）。

## 2. 总体目标

1. 使用 **Godot 4（GDScript 为主）** 将 Alphabounce 复刻到 **Android**，**纯单机离线**运行。
2. 还原核心体验闭环：**挡板接球 → 击碎砖块 → 清关 → 星球地图推进 → 越狱故事线**。
3. 复刻主要系统：球 / 砖块（40+ 类型）/ 增益减益（25 + 7 P-Bonus）/ 导弹 / 无人机 / 敌人 / 确定性关卡生成 / 经济 / 商店 / 飞船 / 角色 / 本地存档。
4. 手感与节奏接近原版；产出可安装的 Android APK/AAB。

## 3. 总体验收标准

- [ ] 可在 Android 真机/模拟器构建并运行（APK/AAB 可安装）。
- [ ] 完整核心循环可玩：单关能开局、接球、清砖、判胜负的关卡流转。
- [ ] 主要系统齐全：球多类型、砖块多类型、25 种增益减益、导弹、无人机、敌人、世界地图与确定性关卡、矿物经济、商店、飞船解锁、本地存档。
- [ ] 单机离线可玩，无网络依赖；进度本地持久化。
- [ ] 帧率稳定（中端机 ≥ 60fps），触控操作顺手。
- [ ] 提供基础音效与音乐、基本 i18n（至少 en + zh）。

## 4. 技术决策（已定 / 待确认）

| 决策点 | 结论 | 说明 |
|---|---|---|
| 引擎 | **Godot 4** | 2D 物理/场景/安卓导出开箱即用，包体小、开源。 |
| 语言 | GDScript 为主，热点用 C#/GDExtension | MVP 用 GDScript，性能瓶颈再改。 |
| 物理方案 | **自定义定步长碰撞**（推荐） | 打砖块手感与"确定性关卡 replay"要求可控、可复现；Godot RigidBody 易抖动。MVP 可用简化自定义运动学。 |
| 资产 | 直接复用 EternalTwin 的 PNG + 字体 | 省去重绘；字体需 woff→ttf/otf 转换。 |
| 后端 | **暂不需要** | 账号/排行榜/云存档列为 Stretch（Phase 12+ 可选）。 |
| i18n | 复用原版文本，先 en + zh | 原版 `Text*.hx` 含 de/en/es/fr 字符串。 |
| 工程根 | `android/` 为 Godot 工程根 | 与 xijia init 的种子需求一致。 |
| **许可证（风险）** | **待用户确认** | 原版 CC **BY-NC-SA（非商业）**、EternalTwin **AGPL-3.0**。若计划**商业发布**，NC 资产不可商用，须自绘资产或取得授权；个人/学习用途通常 OK，但衍生整体需遵守 AGPL。 |

## 5. 分阶段计划

> 每阶段均给出：目标 / 范围拆解 / 资产来源 / 技术要点 / 验收标准 / 后续需求标题（供 `/xijia:start` 创建）。

### P0 · 工程基座
- **目标**：搭好 Godot 工程骨架，能导出空场景到 Android。
- **范围**：Godot 4 工程初始化、`android/` 目录规范、Git、CI 占位、确定性随机工具、`Game` 自动加载与主场景切换框架、导入 EternalTwin 字体与精灵的目录约定。
- **资产**：`EternalTwin-Alphabounce/frontend/src/static/fonts/`、`images/`。
- **技术要点**：`project.godot` 安卓导出配置（包名、图标、横屏/竖屏）；`Random.hx` 对应确定性 PRNG（如 xoshiro）保证关卡可复现。
- **验收**：[ ] Godot 工程可打开；[ ] 空主场景能在 Android 运行；[ ] 字体/一张精灵成功导入并显示；[ ] 场景切换框架就绪。
- **后续需求**：`AB-P0 工程基座与安卓导出`

### P1 · 核心玩法 MVP（对应既有种子需求）
- **目标**：最小可玩——挡板、1 球、基础砖块、单关、计分、失败判定。
- **范围**：挡板（envelope）触控移动；球定步长运动+挡板/边界反弹；一类可破砖块；清关（砖块清空）与失败（球落底）；基础 HUD（分数/命）。
- **资产**：`mcPad/`、`mcBall/`、`mcBlock/`、`ballMain/`。
- **技术要点**：自定义球物理（入射角随挡板命中位置变化）；碰撞用网格/区域检测；固定 timestep（`_physics_process`）。
- **验收**：[ ] 触控移动挡板；[ ] 球碰挡板/墙反弹；[ ] 击碎一类砖；[ ] 清空过关、球落底判负；[ ] HUD 显示分数。
- **后续需求**：`AB-P1 核心玩法 MVP`（即 `20260818205718-AB-安卓工程初始化.md` 细化）

### P2 · 砖块（conglomerate）系统（40+ 类型）
- **目标**：支撑多种砖块行为与数据驱动配置。
- **范围**：砖块数据表（耐久/是否可破/得分/掉落/特殊行为）；至少实现核心类型（普通、高耐久、不可破、多段、特殊触发）；砖块破坏特效与掉落字母。
- **资产**：`mcBlock/`、`mcBlockSmc/`、`blockMissile/`、`part*/`。
- **技术要点**：砖块为 `Resource` 数据 + 节点预制；行为用状态/策略模式；参考 `Block.hx` 与原版 `Block.hx`。
- **验收**：[ ] 数据驱动增删砖块类型；[ ] ≥ 5 种行为砖块可用；[ ] 破坏有特效与字母掉落；[ ] 与原版行为对照无重大偏差。
- **后续需求**：`AB-P2 砖块系统（40+类型）`

### P3 · 球系统（多类型 / 多球）
- **目标**：多种球与多球机制。
- **范围**：球类型数据（攻击力、穿透、Safe 等）；Multiball 多球生成与回收；球全失 → 关卡失败；球与多球的碰撞优先级。
- **资产**：`el/Ball.hx` 逻辑、`mcBall/`、`ballMain/`、`mcSpeederBall/`。
- **技术要点**：球列表管理；多球碰撞去抖；Safe Ball 落地后恢复攻击等特性。
- **验收**：[ ] ≥ 3 种球类型行为正确；[ ] Multiball 正常增减；[ ] 全球丢失判负；[ ] 手感接近原版。
- **后续需求**：`AB-P3 球系统（多类型/多球）`

### P4 · 增益与减益（25 种 + 7 P-Bonus）
- **目标**：还原字母掉落触发的 25 种效果与 7 种飞船 P-Bonus。
- **范围**：字母掉落→拾取→触发框架；18 Bonus + 7 Malus 效果（Attraction/Barrier/Chaos Field/Extension/Frenzy/Halo/Javelin/Laceration/Multiball/Nebula/Open/Quasar/Regeneration/Sapper/Terraforming/Ultraviolet/Vendetta/Xenox；Diminish/Gelato/Indigestion/Kamikaze/Whisky/Yoga/Zealot）；P-Bonus 随飞船切换。
- **资产**：`fx*/`、`ev/*` 对应精灵、`mc*/`。
- **技术要点**：效果系统用事件/组件化；INSOMNIA 飞船免疫 Malus 的规则；P-Bonus 与飞船绑定。
- **验收**：[ ] 掉落/拾取/触发管线通；[ ] 25 种效果可配置并验证；[ ] P-Bonus 随飞船变化；[ ] Malus 免疫规则正确。
- **后续需求**：`AB-P4 增益与减益系统（25+7）`

### P5 · 导弹与无人机
- **目标**：挡板导弹与自动无人机。
- **范围**：导弹发射（左右，有限数量，Provision 补充）、命中伤害；无人机部署（球撞挡板触发）、自动索敌攻击。
- **资产**：`el/shot/Missile.hx`、`ev/Drone.hx`、`mcMissile/`、`mcDrone/`、`mcQueueDrone/`。
- **技术要点**：导弹弹药计数与补充规则（浏览器版/DSi 版差异需定）；无人机生命周期与索敌。
- **验收**：[ ] 导弹可发射/计数/补充；[ ] 无人机自动攻击目标；[ ] 与原版行为一致。
- **后续需求**：`AB-P5 导弹与无人机`

### P6 · 敌人与危险
- **目标**：会反击的砖块/敌人（激光等）。
- **范围**：敌人类砖块（如 Dragon/Insect/Generator 射击）、激光伤害挡板、危险预警。
- **资产**：`ev/Dragon.hx`、`ev/Generator.hx`、`mcMonster/`、`mcDragon/`、`mcInsect/`、`mcLaser/`、`mcWarning/`。
- **技术要点**：敌人 AI 与射击节奏；激光对挡板/球的影响（原版伤挡板并可能丢关）。
- **验收**：[ ] 敌人按节奏射击；[ ] 激光命中产生预期后果；[ ] 难度可控。
- **后续需求**：`AB-P6 敌人与危险`

### P7 · 关卡生成与世界地图
- **目标**：确定性程序生成 + 27 星球推进地图。
- **范围**：确定性关卡生成器（seed 复现，参考 `Random.hx`/`Level.hx`）；星球节点、迷雾/解锁、Earth 终点与地图碎片(Sonar)；关卡难度参数。
- **资产**：`navi/Map.hx`、`worldAsteroMap/`、`mcMapAsteroide/`、`mcMapIcon*/`、`landerPlan*/`。
- **技术要点**：同 seed 同关卡（保证 replay/分享）；星球图状态机；碎片收集触发结局。
- **验收**：[ ] 同 seed 生成一致；[ ] 27 星球地图可导航；[ ] 迷雾/解锁正确；[ ] 到达 Earth 触发结局。
- **后续需求**：`AB-P7 关卡生成与世界地图`

- **验收**：[ ] 矿物增减正确；[ ] 商店购买生效；[ ] **28** envelope 解锁/切换改变 P-Bonus；[ ] 升级持久化。

## 6. 风险与待决问题

1. **许可证（高优先）**：原版 CC BY-NC-SA（非商业）、EternalTwin AGPL-3.0。**若计划商业发布，NC 资产不可商用**，须自绘或授权；当前以个人/学习为主可接受，但衍生整体需遵守 AGPL。→ 需用户拍板。
2. **物理手感**：打砖块手感是复刻成败关键，需自定义定步长碰撞 + 大量调参，建议 P1 即建立手感基线。
3. **砖块 40+ 类型行为**：需逐一定义，依赖 `Block.hx` + 设计文档交叉校验，工作量集中在 P2/P6。
4. **资产转换**：EternalTwin 字体为 woff，Godot 需 ttf/otf；精灵多为序列帧，需规划 `SpriteFrames` 切分。
5. **范围目标（2026-08-20 修订）**：目标改为**全量复刻**（非 MVP 子集）。P4/P7/P8/P8b 体量最大，按依赖顺序推进；验收以 **P16 全量矩阵** 为准。
6. **后端取舍**：账号/云存档/排行榜本期不做（纯单机）；如后续需要，EternalTwin 的 Node+Redis 可作参考但需重写适配。
