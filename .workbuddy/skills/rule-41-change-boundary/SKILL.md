# 目标

确保每次改动可解释、可回归、可追溯，避免无关扩散改动。

# 约束

1. 改动前明确模块边界、计划文件、影响调用方与回归点。
2. 改公共逻辑或跨模块契约前，先说明为何不能在模块内闭环，并评估调用方。
3. Bug 修复仅修改导致问题的最小闭环；「更优雅」不构成扩大范围的理由。

> Gate-1 需求文档的「复用映射 / 代码落点」「切片拆解」「回归验证点」由 `pipeline_guard.py --check-plan` 在工具层校验，本规则不重复要求输出模板。
