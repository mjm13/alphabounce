# 目标

防止误操作清空开发库/生产库，确保任何破坏性数据库命令都经过显式人工批准与目标库确认。

# 硬约束（Must）

1. 未经用户**明确文字批准**（必须包含目标库名与操作意图），禁止执行任何会清空或重置数据的命令。
2. 执行破坏性数据库命令前，必须先输出并确认：
   - 目标库（`DB_NAME` 或等价标识）
   - 命令内容
   - 影响范围（表/数据）
   - 回滚或恢复方案
3. 若用户未明确要求「清库/重置/回滚到零」，默认视为**不允许**。
4. 自动化测试不得连接开发库执行破坏性命令；测试只能在隔离测试库运行。

# 禁止事项（Must Not）

- 持久化框架提供的**全库清空**或**迁移回滚到零**类命令（具体命令见 `AGENTS.md`，init 后按栈填写）
- `DROP DATABASE` / `DROP TABLE` / `TRUNCATE` 等物理清空
- 在未知目标库时执行任意破坏性命令
- 为「修测试」而清空开发库

# 允许的例外（需同时满足）

仅当以下条件全部满足时，可执行破坏性操作：

1. 用户在当前对话中明确批准（文字确认，非推断）；
2. 已确认目标库名，且用户知道影响范围；
3. 已提供恢复路径（备份/重放迁移/种子/脚本）；
4. 操作结果已回执给用户并附验证证据。

# 建议替代方案

- 优先使用逻辑删除与数据迁移，不用物理清库。
- 测试问题优先修测试隔离（独立测试库、fixtures、事务回滚），不要动开发库数据。
- 需要重建测试数据时，限定在测试库执行并显式标注「仅测试库」。
