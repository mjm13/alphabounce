# Gate-1 方案与验收

## 页面布局预览

不适用（无 UI 触达）

## 验收标准

- [ ] **AC-1**：GIVEN 一份无 `version` 字段的 legacy 存档（v0）WHEN `load_from` 加载 THEN 不崩溃、字段正确读入，且随后 `save_to` 写出的存档含 `version == SAVE_VERSION`（证明 legacy 被识别并升级）。
  - **反例（本 AC 排除）**：legacy 存档加载报错、字段丢失或回写仍无版本。
- [ ] **AC-2**：GIVEN 当前版本（`SAVE_VERSION`）存档 WHEN `save_to` 后 `load_from` 往返 THEN 全部字段相等且读出的 `version == SAVE_VERSION`。
  - **反例（本 AC 排除）**：往返字段漂移或版本字段缺失。
- [ ] **AC-3**：GIVEN 一份 `version > SAVE_VERSION` 的未来存档 WHEN `load_from` 加载 THEN 发出 `save_version_warn` 信号、不崩溃、已有字段尽力读入。
  - **反例（本 AC 排除）**：未来存档导致崩溃或静默丢弃。
- [ ] **AC-4**：GIVEN legacy 存档 WHEN 经 `_migrate` 钩子 THEN 加载后写回版本被提升为 `SAVE_VERSION`（迁移路径可达，为后续结构性迁移预留扩展点）。
  - **反例（本 AC 排除）**：legacy 始终停留在 v0、迁移钩子从未触发。

## 实现方案

- 架构 / 关键改动：在 `player_data.gd` 增加 `const SAVE_VERSION := 1` 与 `signal save_version_warn(loaded_version: int, current_version: int)`；将 `save()`/`load_data()` 重构为委托 `save_to(path)`/`load_from(path)`（默认路径 `SAVE_PATH`，保持 Autoload 行为不变）；`save_to` 写入含 `version` 的 dict；`load_from` 解析 `version`（缺省 0），`> SAVE_VERSION` 时发 `save_version_warn` 并尽力加载，`< SAVE_VERSION` 时调用 `_migrate(from_ver, data)` 钩子（当前无结构性变更，预留按版本区间转换扩展点）。
- 复用映射 / 代码落点：

  | 已有模块/服务 | 可复用接口/函数/表 | 关系类型 | 精确坐标 |
  |---|---|---|---|
  | `player_data.gd` | `SAVE_PATH` / `_reset_default` / `saved` / `loaded` | 扩展（加版本与迁移） | `game/scripts/systems/player_data.gd` |

- 切片拆解：
  1. [AC-1/AC-2/AC-3/AC-4] `player_data.gd` 增加版本常量、信号与 `save_to`/`load_from`/`_migrate`；新增 `game/tests/test_save_version.gd` 覆盖四 AC。
- 回归验证点：`tools/godot_std/Godot_v4.7.1-stable_win64_console.exe --headless --path game tests/test_save_version.tscn`
