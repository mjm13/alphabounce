# 20250101130001-关卡网格与关卡数据系统

# Gate-0 澄清与范围

## 原始诉求（verbatim，禁止改写）

> 实现关卡网格管理和关卡数据加载系统，支持 JSON 配置表定义方块布局。

## 歧义登记

歧义登记: none（已逐句复核，触达面：关卡网格；确认人:Agnes；日期:2025-01-01）

## 业务目标

通过 JSON 配置表定义关卡中方块的排列，使关卡设计数据化、可编辑、可回溯。

## 用例 / 用户故事

不适用（类型=技术）

## 范围与切片

> 背景：Godot 4.x 项目；block.gd 已有 BlockType 枚举；game.gd 有 World 节点（但无内容）。
> In Scope 只写能力边界。

### In Scope（本期交付）

- LevelData 类：解析 JSON 关卡配置文件（格子矩阵 + 方块类型映射）
- GridManager 类：维护世界坐标系 ↔ 网格坐标系的转换（GRID_SIZE=32px）
- LevelLoader 单例（Autoload 或 Game 子节点）：加载并实例化方块
- 至少 3 个示例关卡 JSON（level_001.json ~ level_003.json），覆盖不同方块排列
- 方块按网格位置实例化到 World 节点下

### Out of Scope

- 不做关卡编辑器（原因：后续独立需求；重开触发：新 PRD）
- 不做动态关卡生成（原因：首期硬编码关卡；重开触发：R08 敌人系统后）
- 不做关卡选择 UI（原因：依赖 R05 任务系统解锁逻辑；重开触发：R05 完成后）
- Gate-1 前不接入 Mission/Shop 数据（原因：数据耦合；重开触发：R05/R06）

### 待确认问题与延期项（Open Questions & Deferred）

**Must-Confirm**

- OQ-001：网格大小 → 结论：GRID_SIZE=32（与 Block.tscn RectangleShape2D size=30 匹配，留 2px 间隙）
- OQ-002：关卡文件格式 → 结论：JSON，字段 `grid_width`, `grid_height`, `blocks: [[type,x,y],...]`

**Deferred**

- DEF-001：关卡难度递进曲线（当前仅保证功能，数值平衡后续调整）

## 验收标准

- [ ] **AC-1**：LevelData 可从 JSON 文件正确解析关卡数据（网格宽度、高度、方块列表）
  - **反例（本 AC 排除）**：解析结果为空或字段映射错误
- [ ] **AC-2**：GridManager.world_to_grid() 和 grid_to_world() 双向转换正确（误差 < 1px）
  - **反例（本 AC 排除）**：转换后坐标偏移超过 GRID_SIZE/2
- [ ] **AC-3**：LevelLoader 加载 level_001.json 后，World 节点下出现正确数量和位置的方块
  - **反例（本 AC 排除）**：方块数量为 0 或位置整体偏移
- [ ] **AC-4**：至少 3 个不同布局的示例关卡 JSON（含不同方块类型混合）
  - **反例（本 AC 排除）**：仅有 1 个或类型单一
- [ ] **AC-5**：Godot Editor 打开 Game.tscn，关卡方块正确渲染（占位色块）
  - **反例（本 AC 排除）**：Editor 报 JSON 解析错误或节点引用断裂
