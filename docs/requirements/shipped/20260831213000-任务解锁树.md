## 业务目标

在现有线性任务 progression 之上，引入**前置依赖解锁**：任务仅在满足其前置任务（0..N）全部完成后才进入「可接取」状态，使 progression 呈结构化分支（树/森林），而非单一线性链。玩家能直观看到某任务因何被锁定（缺哪些前置）。

## 用例 / 用户故事

1. 作为玩家，我能在任务面板看到每个任务的锁定/可接取/进行中/已完成状态。
2. 作为玩家，当某任务的前置任务全部完成时，该任务自动从「锁定」变为「可接取」。
3. 作为玩家，被锁定的任务会提示其前置依赖（「需先完成：X、Y」），而非无解释地隐藏。

## 范围与切片

> 背景：现有 `MissionData`（`game/scripts/systems/mission_data.gd`）仅有 `cond_type/cond_value` 触发条件，**无**前置字段；`MissionManager.check_conditions()` 在 `level_complete` 后把满足条件任务置为 `0 进行中`，无前置判断。本需求在二者之上增量加入解锁树。
> In Scope 只写能力边界。

### In Scope（本期交付）

- `MissionData` 扩展 `requires: Array[String]`（前置任务 id 列表，允许 0..N，构成 DAG，禁止环）。
- `MissionManager` 新增解锁评估：任务进入「可接取」的充要条件是「前置任务 status 全 == 1」**且**原 `cond_met` 满足；否则保持「锁定」（-2 新增状态）。
- `MissionManager` 在 `level_complete` 信号后仍经 `check_conditions` 触发，并调用 `check_unlock`；保持 INV-001（单调推进）与 INV-002（仅 level_complete 后检查）不变量。
- `MissionPanel` 渲染锁定态与前置依赖提示文本。

### Out of Scope

- 不做在线任务同步（原因：离线单机优先；重开触发：后端需求）
- 不做任务奖励自动发放到背包（原因：依赖 R06 商店；重开触发：R06 完成后）
- 不做解锁树可视化地图/节点图（原因：首期列表内依赖提示即可；重开触发：独立 UI 需求）→ 见 DEF-001

## 领域影响
- **BC**：Mission（任务 BC，与 R04 任务系统同一边界；不新增 BC）
- **术语**：解锁树（unlock tree）= 任务间前置依赖 DAG；「锁定」(-2) = 前置未全达成(status<0)；「可接取」(-1) = 前置全达成(status≥0)但原条件未满足；「进行中」(0) = 条件满足（沿用 R04）。前置达成判定为 status≥0（0/1），可接取(-1) 不计入。
- **INV**：沿用 R04 不变量 INV-001（状态单调推进 -2→-1→0→1）、INV-002（仅 level_complete 后检查）；新增 INV-003（`requires` 构成无环 DAG，加载期校验拒绝环，见 AC-3）。前置达成 = status ≥ 0；可接取(-1) 不计入前置达成（见 AC-1）。
- 复用现有 `MissionData`/`MissionManager`，无新建模块。

# Gate-1 方案与验收

## 页面布局预览

> 复用现有 MissionPanel；差异：每项增加状态徽标（锁定🔒/可接取/进行中/已完成）与锁定时的前置提示行。
```
[任务面板]
 ├ 任务A  [已完成 ✓]
 ├ 任务B  [可接取]   （前置：A 已完成）
 └ 任务C  [锁定 🔒]  需先完成：A、B
```

## 验收标准

- [ ] 覆盖要求：每条 In-Scope 能力至少 正常/空/错误/无权限；≥1 条可执行断言
- [ ] **AC-1**：GIVEN 任务 T 配置 `requires=[P]` WHEN P 的 `status` 变为 `≥0`（已达成，被 `check_conditions` 置为 0/1）THEN T 由锁定(-2)变为可接取(-1)（发出 `mission_updated(T,-1)`）；WHEN T 自身 `cond_met` 满足 THEN T 由可接取(-1)变为进行中(0)（发出 `mission_updated(T,0)`）
  - **反例（本 AC 排除）**：P `status<0`（未达成）时 T 不得变为可接取；P 已达成但 T `cond_met` 未满足时 T 仅显示「可接取」(-1) 而非「进行中」(0)
- [ ] **AC-2**：GIVEN 任务 T 配置 `requires=[P,Q]` WHEN 仅 P 达成(≥0)、Q 未达成(<0) THEN T 保持锁定(-2)，且面板提示「需先完成：Q」
  - **反例**：仅部分前置达成不得解锁
- [ ] **AC-3**：GIVEN `requires` 形成环（如 A 需 B、B 需 A）THEN 加载时不变量检测拒绝该配置（日志告警），不影响其余任务
  - **反例**：不得因环导致死锁/崩溃
- [ ] **AC-UI-1**：MissionPanel 对锁定任务渲染 🔒 与前置提示文本，可接取任务渲染对应徽标

- 架构 / 关键改动：`MissionData` 增加 `requires: Array[String]`；`MissionManager` 增加 `check_unlock()` 与状态 `-2 锁定`；`MissionPanel` 增加锁定渲染。
- 复用映射 / 代码落点：

  | `mission_panel.gd` | 任务列表渲染 | 扩展（锁定态 + 提示） | `game/scripts/ui/mission_panel.gd` |

- 影响面与回归范围：仅任务系统；回归 R04 任务系统既有 3 示例任务（无 requires 时行为不变）。
- 切片拆解：
