# 20250101130000-Pad发射台系统

# Gate-0 澄清与范围

## 原始诉求（verbatim，禁止改写）

> 实现球体发射台（Pad），支持触摸拖动瞄准、松手发射，球从Pad位置沿瞄准方向射出。

## 歧义登记

歧义登记: none（已逐句复核，触达面：Pad发射台交互；确认人:Agnes；日期:2025-01-01）

## 业务目标

为玩家提供球体发射的交互入口，是 AlphaBounce 核心玩法的第一环。

## 用例 / 用户故事

1. 作为玩家，我触摸屏幕底部区域看到发射台，拖动方向决定球发射角度
2. 作为玩家，松手后球立即沿瞄准方向以固定速度射出
3. 作为玩家，发射台在球发射后保持可见，可再次发射（如有多球）

## 范围与切片

> 背景：Godot 4.x 项目；已有 `ball.gd` 基础物理框架；已有 `game.gd` 主场景骨架；触摸输入映射已配置 `tap_left`/`tap_right`。
> In Scope 只写能力边界。

### In Scope（本期交付）

- Pad 节点类：位置固定于屏幕底部中央，可视化（占位色块即可）
- 触摸瞄准：`InputEventScreenDrag` 检测拖拽方向和角度
- 发射触发：松手时实例化 Ball 并从 Pad 位置沿方向发射
- 发射方向可视化：拖拽时显示瞄准线（虚线或箭头）
- 与 Game 场景集成：Pad 作为 `Game.tscn` 的子节点

### Out of Scope

- 不做多球数量管理（原因：依赖 R07 玩家存档；重开触发：R07 完成后）
- 不做 Pad 位置移动（原因：固定布局；重开触发：新需求 PRD）
- 不做发射音效（原因：R10 音频系统；重开触发：R10 完成后）
- Gate-1 前不接入真实关卡数据（原因：依赖 R02；重开触发：R02 完成后）

### 待确认问题与延期项（Open Questions & Deferred）

**Must-Confirm**

- OQ-001：瞄准方向精度 → 结论：角度量化到 5° 步进即可（避免过于敏感）
- OQ-002：Pad 球速 → 结论：复用 ball.gd 现有 `SPEED = 300.0`（经 `launch()` 内部使用，本需求不硬编码速度）

**Deferred**

- DEF-001：发射台位置可配置（当前硬编码 Y=540，viewport_height-60）→ 后续 ADR 评估是否参数化
