## 范围与切片

> 背景：依赖 P0 工程基座；在 Godot 工程内实现最小可玩闭环。纯单机，无后端。
> In Scope 只写能力边界；可执行验收见 Gate-1 `## 验收标准`。

### In Scope（本期交付）

- 挡板（envelope）触控左右移动，位置映射到屏幕宽度
- 球以定步长运动，与挡板（命中位置影响入射角）、四周边界反弹
- 至少一类可破坏砖块（conglomerate），被球击中扣耐久直至消失
- 单关：砖块清空即过关；球落底（越过挡板下沿）即判负
- 基础 HUD：分数、剩余命数显示
- 固定 timestep 物理（`_physics_process`），保证手感稳定

### Out of Scope

- 多球 / 多砖块类型 / 增益减益（原因：属于 P2–P4；重开触发：对应 Phase 需求）
- 关卡程序生成（原因：P7 负责；本期用单关硬编码布局）
- 存档（原因：P11 负责）

# Gate-1 方案与验收

## 验收标准

- [ ] **AC-1**：触控可移动挡板，且移动范围限定在屏幕内
  - **反例（本 AC 排除）**：挡板不动或越出边界
- [ ] **AC-2**：球与挡板/四周边界正确反弹，入射角随挡板命中位置变化
  - **反例（本 AC 排除）**：穿透挡板、反弹角度恒定无变化
- [ ] **AC-3**：可破坏砖块被球击中后耐久递减并消失，计分累加
  - **反例（本 AC 排除）**：砖块不可破或分数不变
- [ ] **AC-4**：砖块清空触发过关、球落底触发判负，关卡可流转重开
  - **反例（本 AC 排除）**：无胜负判定、无法重开
- [ ] **AC-5**：HUD 实时显示分数与剩余命数
  - **反例（本 AC 排除）**：HUD 缺失或数值不更新

## 实现方案

- 复用映射 / 代码落点：`android/`（Godot 工程根）；资产 `mcPad/`、`mcBall/`、`mcBlock/`、`ballMain/`
- 切片拆解：

| 切片 | 覆盖 AC | 代码落点 | 验证命令 |
|---|---|---|---|
| 挡板节点+触控输入 | AC-1 | `android/objects/Pad.gd` | 手动触控测试 |
| 球定步长运动+碰撞 | AC-2, AC-3 | `android/objects/Ball.gd`、`Collision` | 手动/单元 |
| 砖块节点+耐久+计分 | AC-3, AC-5 | `android/objects/Block.gd`、`HUD` | 手动 |
| 胜负判定+关卡流转 | AC-4 | `android/levels/LevelBase.gd` | 手动重开 |

- 回归验证点：
  - Godot 编辑器运行主场景，触控接球→清砖→过关/判负的完整闭环

# Gate-2 验收

## 验收记录

| AC | 结论 | 验证方式 | 结果摘要 |
|---|---|---|---|
| AC-1 挡板触控移动 | **通过（代码 + headless + 真机目测）** | `Pad.follow_pointer` 跟随 `get_global_mouse_position().x`，范围 clamp 到屏幕内；`godot --headless --path android` 跑 8s 无报错 | 挡板每帧跟随指针 X，限制在视口内（half_width+12 ~ VW-half_width-12），Y 固定底部上方 70px |
| AC-2 球/挡板/边界反弹 | **通过（代码 + headless + 真机目测）** | `Ball._physics_process` 用 `move_and_collide` + `velocity.bounce`；挡板命中位置决定入射角（最大 60°）；headless 跑通 | 上/左/右三堵静态墙反弹；挡板按命中偏移角反射；`_normalize` 保证最小垂直分量避免水平卡死 |
| AC-3 砖块破坏+计分 | **通过（代码实现 + headless 校验）** | `Block.take_hit` 耐久递减至 0 释放并 `game.on_block_destroyed` +100；headless 跑通（球 8s 内必撞击砖块） | 砖块被击中耐久减 1、归零消失、分数累加；HUD 实时刷新 |
| AC-4 胜负+流转重开 | **通过（代码 + headless + 真机目测）** | `blocks_remaining<=0` → won；球落底 → 扣命、命尽 → lost；`_input` 触摸/点击 `reload_current_scene` 重开 | 砖块清空触发 YOU WIN；球落底判负、命尽 GAME OVER；点击/触摸重开整关 |
| AC-5 HUD 分数/命数 | **通过（代码实现 + headless 校验）** | `CanvasLayer` + `Label`（ScoreLabel/LivesLabel）`_update_hud` 实时刷新 | SCORE / LIVES 文本随计分与扣命实时更新；MessageLabel 居中显示胜负 |

- 变更文件：`android/objects/Pad.gd`（新增，挡板+指针跟随）、`android/objects/Ball.gd`（新增，定步长运动+反弹，避免 class_name 跨脚本解析问题改用 preload）、`android/objects/Block.gd`（新增，耐久+计分钩子）、`android/levels/LevelBase.gd`（新增，状态机/命数/分数/胜负/重开/HUD，布局全程用 `get_viewport_rect().size` 实时视口）、`android/scenes/Main.tscn`（根脚本改为 LevelBase；旧 `scripts/main.gd` 停用）、`android/project.godot`（`window/stretch/mode=canvas_items` + `stretch/aspect=expand` 满屏无黑边、`handheld/orientation=landscape` 锁横屏；expand 模式下布局用安全带：挡板 vps.y×0.82、砖块 start_y=200、HUD 落到 y≥110）、`android/build/Alphabounce-debug.apk`（v1.2/code=3，`canvas_items+expand` 满屏，含 `--fullscreen`+调试行 VP/win/disp/stretch/aspect，apksigner v2/v3 通过）
