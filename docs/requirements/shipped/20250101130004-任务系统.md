# 20250101130004-任务系统

# Gate-0 澄清与范围

## 原始诉求（verbatim，禁止改写）

> 实现任务系统：任务数据配置、条件检查、状态管理、任务面板 UI。

## 歧义登记

歧义登记: none（已逐句复核，触达面：任务系统；确认人:Agnes；日期:2025-01-01）

## 业务目标

通过任务引导玩家 progres，完成关卡/收集物品等目标，给予奖励，构成游戏 progression 循环。

## 用例 / 用户故事

1. 作为玩家，我能打开任务面板查看当前任务列表
2. 作为玩家，任务完成后获得奖励物品（导弹/特殊球体）
3. 作为玩家，已完成的 task 显示为已完成状态，未开始的 task 显示为锁定状态

## 范围与切片

> 背景：已有 glossary.md 定义 Mission 术语；架构文档提到 MissionInfo 数据层。首期支持 3 个示例任务。
> In Scope 只写能力边界。

### In Scope（本期交付）

- MissionData 类：解析任务 JSON 配置（条件、奖励、解锁要求）
- MissionManager 单例（Autoload）：任务状态机（-1未开始/0进行中/1已完成）、条件检查
- 至少 3 个示例任务 JSON（`resources/missions/mission_001.json` 等）
- MissionPanel.tscn：任务列表 UI（展开/收起面板）
- game.gd：关卡完成后触发任务条件检查

### Out of Scope

- 不做在线任务同步（原因：离线单机优先；重开触发：后端需求）
- 不做动态任务生成（原因：首期硬编码；重开触发：后续 PRD）
- 不做任务奖励自动发放到背包（原因：依赖 R06 商店系统；重开触发：R06 完成后）
- 不做任务提示/通知动画（原因：首期简化；重开触发：独立需求）

### 待确认问题与延期项（Open Questions & Deferred）

**Must-Confirm**

- OQ-001：任务条件类型 → 结论：首期支持 3 种：COMPLEVE_LEVEL（完成关卡）、COLLECT_BLOCKS（消除N个方块）、REACH_SCORE（达到指定分数）
- OQ-002：任务面板位置 → 结论：右侧悬浮面板，可拖拽收起

**Deferred**

- DEF-001：任务解锁树（前置任务完成才显示）→ 二期实现
