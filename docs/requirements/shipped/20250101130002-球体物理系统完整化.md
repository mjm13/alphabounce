# 20250101130002-球体物理系统完整化（Godot Physics2D集成）

# Gate-0 澄清与范围

## 原始诉求（verbatim，禁止改写）

> 将 ball.gd 从自定义速度追踪迁移到 Godot CharacterBody2D + move_and_slide()，接入 Physics2D 碰撞系统。

## 歧义登记

歧义登记: none（已逐句复核，触达面：球体物理；确认人:Agnes；日期:2025-01-01）

## 业务目标

使球体物理与 Godot 内置碰撞系统完全兼容，确保与方块、边界、敌人的碰撞检测准确可靠。

## 用例 / 用户故事

不适用（类型=技术）

## 范围与切片

> 背景：当前 `ball.gd` 使用手动 `position += velocity * delta` 和边界 clamp，未使用 Godot Physics2D。
> In Scope 只写能力边界。

### In Scope（本期交付）

- 重构 ball.gd 使用 `CharacterBody2D.move_and_slide()` 替代手动位置更新
- 配置 CollisionShape2D 为 CircleShape2D（已在 Ball.tscn 中，radius=10）
- 配置正确的碰撞层/掩码（layer=4(ball), mask=5(block+boundary)）
- 边界反弹：使用 Godot PhysicsServer 或 CollisionShape2D 配合 Area2D 边界
- 保留原有 `launch(direction)` 接口（Pad 依赖此 API）
- 保留 `get_move_velocity()` / `is_launched_flag()` / `get_type()` 接口

### Out of Scope

- 不做特殊球体效果（火焰弹跳、冰冻减速等）（原因：后续需求；重开触发：独立 PRD）
- 不做导弹物理（原因：R09 导弹系统；重开触发：R09）
- 不做球体重力（AlphaBounce 原版无重力，纯弹跳）
- Gate-1 前不修改 Block 碰撞层（原因：依赖 R04；重开触发：R04 同时实现）

### 待确认问题与延期项（Open Questions & Deferred）

**Must-Confirm**

- OQ-001：边界碰撞实现方式 → 结论：使用 4 个 StaticBody2D 边界板（Top/Bottom/Left/Right），ball.gd 通过 body_entered 信号检测
- OQ-002：物理步长 → 结论：Godot 默认 fixed_process 1/60s，无需修改

**Deferred**

- DEF-001：ball.gd 原 BOUNCE_DAMPING 0.95 → 迁移后 Godot 物理默认弹性系数 0.0，需在材质上设置 restitution=0.95

## 原版对等基线（完全对标，新增 · 关联 R17）

- 球体物理须严格对齐原版 `el/Ball.hx`：无重力纯弹跳，速度模长恒定，反弹角度由入射法向决定（`velocity.bounce(normal)` 等价）
- **当前偏离（须修正）**：`game/scripts/entities/ball.gd` 仍用手写 `step_physics()`（`position += velocity*delta`）+ `check_boundaries()` 手动钳制，违反 ADR-001 与物理对等；由 R17 负责重构为 `move_and_slide()`
- 弹性/速度常量换算：原版帧节拍 → Godot 单位/秒，数值对齐由 R16/R17 提供
- 真机手感验收：见 R17 AC-5

## 原型对齐与偏离

参照源项目 `frontend/src/haxe/el/Ball.hx` 的物理逻辑（速度+方向+弹跳），Godot 侧用 CharacterBody2D 替代手动 update()。偏离点：原版 Pixi.js 无内置物理，Godot 侧需适配 Physics2D 约束。
