# 20260101130018-Debug验收载具与测试框架

# Gate-0 澄清与范围

## 原始诉求（verbatim，禁止改写）

> 建立真机独立验收载具（DebugLauncher + 各需求 debug 场景入口）与自定义测试框架（test_base.gd + test_suite.tscn），作为 R01–R18 全部需求真机验收的统一入口与 AC 自检基础设施。

## 歧义登记

歧义登记: none（已逐句复核；确认人:meijianming；日期:2026-08-29）

## 业务目标

解除 20 个需求在 Gate-2 阶段的验收阻塞：任何需求都能**独立构建 debug 包 → 真机启动 → 经 DebugLauncher 点选本需求 → 进入 debug 场景 → AC 自检打印 PASS/FAIL → 截图取证**，无需先完成其他需求。

## 用例 / 用户故事

1. 作为验收者，我在真机启动 debug 包后看到需求菜单，点选任一需求即进入其独立验收入口。
2. 作为验收者，debug 场景内嵌 AC 自检，logcat 可直接 grep `<REQ_ID>_AC-n PASS/FAIL`。
3. 作为开发者，我用 `test_base.gd` 编写断言，`godot --headless --quit tests/test_suite.tscn` 跑回归。

## 范围与切片

### In Scope（本期交付）

- **DebugLauncher 场景/脚本**：`game/debug/debug_launcher.tscn` + `.gd`，真机启动入口，读取内置需求清单动态生成 20 个条目按钮
- **各需求 debug 场景骨架**：`game/debug/<REQ_ID>_debug.tscn`。R19 仅实现自身 **完整** debug 场景；其余 19 个由对应需求实现时填充，R19 仅生成占位（占位场景打印 `<REQ_ID>_AC STUB`，不崩溃）
- **测试基类**：`game/scripts/tests/test_base.gd`，提供 `assert_eq` / `assert_true` / `assert_false` 与 `print_ac(req_id, n, ok)` 规范
- **测试套件场景**：`tests/test_suite.tscn`（AGENTS.md 已承诺测试命令）
- **fixtures 目录**：`game/debug/fixtures/`，仅含 `README.md` 记录 mock 数据 schema 约定（R16 完成后仅替换数据源）
- **debug 生效约束**：`Main.gd` 的 `_ready()` 中 `if OS.is_debug_build(): get_tree().change_scene_to_file("res://debug/debug_launcher.tscn")`，release 包不进入

### Out of Scope

- 各需求 debug 场景的**具体验收逻辑**（由对应需求实现，R19 只建骨架）
- 真实音频/精灵资源搬运（R15 负责）
- release 导出行为调整（release 仍进正常游戏）

### 待确认问题与延期项

- OQ-002：Main 跳转 DebugLauncher 是否影响 release → 结论：仅 `OS.is_debug_build()` 时跳转，release 不受影响

# Gate-1 方案与验收

## 验收标准（真机独立，强制）

- [ ] **AC-1**：debug 构建启动后自动进入 DebugLauncher，菜单显示全部 20 个需求条目（R01–R18 + BASE-1/2 + R19 占位）
  - 反例：菜单为空、条目缺失、崩溃
- [ ] **AC-2**：点选 R19 进入 `R19_debug.tscn`，logcat 含 `R19_AC-1 PASS` … `R19_AC-5 PASS` 全部 PASS
  - 反例：任一 AC FAIL 或无输出
- [ ] **AC-3**：`godot --headless --quit tests/test_suite.tscn` 可运行且退出码 0、无 SCRIPT ERROR
  - 反例：套件场景报错或断言失败
- [ ] **AC-4**：logcat 零 Godot ERROR / SCRIPT ERROR
  - 反例：存在 ERROR 级日志
- [ ] **AC-5**：截图 `docs/evidence/R19.png` 可见 DebugLauncher 菜单与 20 条目
  - 反例：截图无菜单或内容不符

## 实现方案

- **DebugLauncher.gd**：内置 `REQ_ITEMS` 数组（id + 中文名），`_ready()` 循环生成 `Button`，pressed 信号调用 `try_enter(req_id)`；`try_enter` 用 `ResourceLoader.exists(path)` 判断，存在则 `change_scene_to_file`，否则弹出 `Label`「<id> 验收入口未实现」。
- **R19_debug.tscn/.gd**：空 Control 节点 + 脚本，在 `_ready()` 依次调用 `print_ac("R19", 1..5, true)` 验证逻辑（场景加载、按钮生成、test_base 可用、UI 渲染、零错）。
- **test_base.gd**：提供 `assert_eq(a,b,msg)`、`assert_true(c,msg)`、`assert_false(c,msg)`、`print_ac(req_id,n,ok)`，失败累计计数。
- **test_suite.tscn**：根节点 `Node` + 挂载 `test_base.gd` 派生或空脚本，headless 下打印 `TEST_SUITE DONE`。
- **Main.gd**：`_ready()` 加 debug 跳转。

## 回归验证点

- `godot --headless --quit tests/test_suite.tscn`（框架自测）
- `godot --headless --quit` 直接打开 `debug/debug_launcher.tscn` 冒烟

# Gate-2 验收

## 真机独立验收（USB 调试模式 · 强制）

```bash
# 1 构建 debug 包
godot --path game --headless --export-debug "Android" game/bin/AlphaBounce_debug.apk
# 2 USB 安装 + 启动
adb -s <DEVICE_SERIAL> install -r game/bin/AlphaBounce_debug.apk
adb shell am start -n com.eternaltwin.alphabounce/com.godot.game.GodotAppLauncher
# 3 DebugLauncher 自动出现（debug 构建）；点选 R19
# 4 AC 断言
adb logcat -d | grep "R19_AC"
# 5 截图
adb shell screencap -p /sdcard/R19.png && adb pull /sdcard/R19.png docs/evidence/R19.png
# 6 零 ERROR
adb logcat -d -v brief | grep -iE "godot|script error"
```
