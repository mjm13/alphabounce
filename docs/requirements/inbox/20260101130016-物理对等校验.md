# 20260101130016-物理对等校验

# Gate-0 澄清与范围

## 原始诉求（verbatim，禁止改写）

> 将球体物理对齐原版手感：使用 Godot `CharacterBody2D.move_and_slide()`（ADR-001），并使其弹跳角度/速度曲线与原版 Pixi 实现一致。

## 歧义登记

歧义登记: none（已逐句复核，触达面：物理手感；确认人:Agnes；日期:2026-08-28）

## 业务目标

让安卓重构版的球体弹跳手感与原版一致（无重力、纯弹跳、反弹角度由入射决定），消除当前手写物理的偏离。

## 用例 / 用户故事

1. 作为玩家，球体弹跳角度/速度与原版一致，无穿墙/卡死/异常加速
2. 作为开发者，ball.gd 使用 `move_and_slide()` 而非手动 `position += velocity*delta`

## 范围与切片

> 背景：当前 `game/scripts/entities/ball.gd` 使用 `step_physics()`（`position += velocity*delta`）+ `check_boundaries()` 手动钳制，违反 ADR-001。原版 `Ball.hx`（Pixi）为无重力纯速度积分+边界反弹。
> In Scope 只写能力边界。

### In Scope（本期交付）

- 重构 ball.gd：以 `CharacterBody2D.move_and_slide()` 驱动物理（ADR-001），移除手动 `position +=` 与边界 clamp
- 边界反弹：由 World 下 4 个 StaticBody2D 边界板经 `move_and_slide` 自动反弹；反弹角度由碰撞法向决定（对齐原版 `velocity.bounce(normal)`）
- 无重力：不设置 `gravity`（对齐原版无重力纯弹跳）
- 速度一致性：`SPEED`/弹性系数换算对齐原版（原版约匀速弹跳；Godot 侧 `velocity` 模长保持恒定，碰撞后按法向反射）
- 接口保持：`launch(direction)`、`get_ball_velocity()`、`get_type()`、`is_launched_flag()` 签名不变（Pad/Block 依赖）

### Out of Scope

- 不做特殊球体效果（火焰/冰冻）（原因：后续需求）
- 不做导弹物理（原因：R11）
- Gate-1 前不修改 Block 碰撞层（原因：依赖 R04）

### 待确认问题与延期项（Open Questions & Deferred）

**Must-Confirm**

- OQ-001：弹性系数 → 结论：Godot `PhysicsMaterial.restitution=1.0`（原版匀速弹跳，无能量损失）
- OQ-002：速度模长保持 → 结论：`move_and_slide` 后 `velocity` 由引擎管理；碰撞回调中按法向反射，不额外衰减

**Deferred**

- （无）

# Gate-1 方案与验收

## 验收标准

- [ ] **AC-1**：ball.gd 物理步进使用 `move_and_slide()`，代码中**不存在**手动 `position += velocity*delta` 路径
  - **反例（本 AC 排除）**：仍残留手写积分
- [ ] **AC-2**：无重力（`gravity`/`acceleration` 默认 0），球体纯弹跳

- [ ] **AC-3**：边界碰撞由 `move_and_slide` + StaticBody2D 自动反弹，反弹角度由法向决定，无穿墙/卡死
  - **反例（本 AC 排除）**：穿墙或角度异常

  - **反例（本 AC 排除）**：真机球不弹/穿墙

- 架构 / 关键改动：重写 `game/scripts/entities/ball.gd` 物理部分；`Ball.tscn` 配 `PhysicsMaterial.restitution=1.0`；Game.tscn World 下 4 个 StaticBody2D 边界
- 切片拆解：

  1. [AC-1, AC-4] 重构 ball.gd：`_physics_process` 用 `move_and_slide()`，保留接口
