### 原版对照结论（AC-4，依据 `Block.hx`）

- **耐久模型**：原版 `life = Math.min(type,5)` 后 `+0.9`，命中 `if(life>=n){ setLife(life-n) } else explode()`。本实现 `hp` 整数化对应：`NORMAL/DURABLE/SPECIAL` 按 `hp` 逐次扣血，归零即销毁，与原版一致。
- **不可破**：原版 `life==null`（STEEL/REDUC/STORM/SWAP/KILL/GLUE）仅 `fxBlink` 永不炸毁。本实现 `UNBREAKABLE` 置 `hp=-1`，仅发 `damaged` 信号、永不销毁，完全吻合。
- **掉字母**：原版标准砖经 `bonusTable[x][y]→newOption` 掉落增益字母。本实现 `drop_letter` 砖销毁生成 `Pickup`（字母拾取物），P4 接管实际效果，机制对应。
- **特殊触发**：原版 REDUC/STEEL 等 `onDamage` 在受伤/销毁时触发特殊效果。本实现 `SPECIAL` 销毁时发射 `special_triggered(block, special_id)` 信号，效果接管留待 P4。
- **Out of Scope 一致**：原版 BALL/BOOM/MINE/DRAGON 等异种（敌人/危险类）按 P2 文档明确归 P4/P6，本期不实现，无偏差。

- **集成（非阻塞）**：P2 交付的是「数据驱动的砖块类型系统」，当前由独立 `Block` 内联类承载并在 `blocks_test` 中自测通过。下一步（可在 P1 或 P2 收尾阶段）将 `BlocksRegistry` + `BlockDef` 接入 P1 的 `android/objects/Block.gd`：让 P1 的 `Block` 节点 `preload("res://scripts/brick_system.gd")` 读取 `BlockDef`，以 `def.hp/def.behavior/def.color` 替代硬编码 `durability`，从而把 44 种类型真正落到游戏关卡。
- **Exotic 类型**：BALL/BOOM/MINE/DRAGON 等异种按文档归 P4/P6，本期不实现。
