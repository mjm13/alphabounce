## 范围与切片

> 背景：依赖 P8（矿物/商店/解锁 envelope）、P7（星球→解锁）、P3（球装备）、P4（P-Bonus 随 envelope）、P5（导弹/无人机/地雷装备）。  
> **修正**：「3 艘飞船」= **舰队槽位数**，非 envelope 总数（见 `alphabounce-facts.md` §2）。

### In Scope（本期交付）

- **舰队槽位**：初始 3 槽；`Additional Ship` 类效果扩至 4 槽（接口预留，效果触发可 Deferred 到 P4）
- **Loadout 模型**：每艘 envelope **2–6 装备槽**（`MAX_OPTION=6`）；槽内装备引用全局唯一库存
- **装备类别约束**（与原作一致，校验拒绝非法组合）：
  - 顶置武器（激光/加农）：每船 ≤1
  - 导弹：每船 ≤1
  - 球：每船 ≥1；多球时左右分布（接 P3）
  - 无人机/地雷：可多个；部署顺序与 P5 串行规则一致
  - Extension：无数量上限（受总槽位 6 限制）
  - 护甲：每船 ≤1
  - 杂项（如 Ammo Supplies）：无类别上限（受总槽位限制）
- **Defense**：隐藏属性，每 1 点全来源伤害 -1（Metal Scraps 1 / Steel Plates 2 / Shield 5 / Advanced Shield 7）；BEGNE-TWO 自带 Defense 在 `EnvelopeDef` 标注
- **全游戏唯一装备**：每件装备 ID 全局仅一份；在舰队 envelope 间**重新分配**（非复制）
- **关卡进场**：按当前 envelope loadout 实例化球/导弹/无人机参数（读数据，不改 P1/P3/P5 核心逻辑）
- **7 种 Pad/船体装备**（P3 枚举）作为 loadout 条目，进场改变挡板行为
- **数据表**：`equipment.json`（**Shop 全 catalog**）+ `envelopes.json`（**28 行**）

### Out of Scope

- 商店 UI / 舰队 UI → P9（本需求提供 `FleetService` / `LoadoutValidator` API）
- 存档序列化落盘 → P11（本需求定义 `FleetState` / `InventoryState` 结构）
- 28 种 envelope 美术 → P9/P10 资产同步；逻辑/data **本期全量**
- 字母增益 25+7 效果本体 → P4
- 导弹/无人机行为本体 → P5（本需求只读 loadout 决定**初始参数与顺序**）

# Gate-1 方案与验收

## 验收标准

- [ ] **AC-1**：`LoadoutValidator` 拒绝违反类别约束的组合（如两导弹、零球、双护甲）
  - **反例（本 AC 排除）**：非法 loadout 仍能进场
- [ ] **AC-2**：全局唯一装备：同 ID 不可同时挂在两艘 envelope；重新分配后旧槽位清空
  - **反例（本 AC 排除）**：复制同一件装备到多船
- [ ] **AC-3**：Defense 结算：伤害 5 + Shield(5) → 实际 0；不可破砖/敌人伤害均走同一公式
  - **反例（本 AC 排除）**：Defense 未生效或只对部分来源生效
- [ ] **AC-4**：关卡进场：loadout 中 2 球 + 导弹 + Extension 正确反映到 P3/P5/挡板宽度（可测场景断言）
  - **反例（本 AC 排除）**：loadout 与场上实体不一致
- [ ] **AC-5**：舰队槽位 3→4：第 4 槽 envelope 在首船损失后按顺序替补进场
  - **反例（本 AC 排除）**：首船损失后跳关或直接 Game Over（尚有替补）
- [ ] **AC-6**：数据表增删装备/envelope 类型无需改验证器核心代码（仅 JSON + 枚举扩展）
  - **反例（本 AC 排除）**：每加一件装备改 `.gd` 硬编码
