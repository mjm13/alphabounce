# 20250101130006-玩家存档系统

# Gate-0 澄清与范围

## 原始诉求（verbatim，禁止改写）

> 实现玩家数据持久化：关卡进度、货币、物品库存、任务状态的 JSON 存档/读档。

## 歧义登记

歧义登记: none（已逐句复核，触达面：玩家存档；确认人:Agnes；日期:2025-01-01）

## 业务目标

玩家关闭游戏后重新打开，保留所有进度（关卡、物品、任务状态），实现无缝续玩。

## 用例 / 用户故事

不适用（类型=技术）

## 范围与切片

> 背景：Godot 4.x 提供 UserDirectory 路径（`user://`）用于持久化存储。
> In Scope 只写能力边界。

### In Scope（本期交付）

- PlayerData.gd（Autoload Node）：玩家状态数据模型
  - current_level: int（当前关卡，从 1 开始）
  - max_level_unlocked: int（最高解锁关卡）
  - stars: int（货币/星星数量）
  - inventory: Dictionary（物品 ID → 数量）
  - missions: Dictionary（任务 ID → 状态）
- save() 方法：序列化到 `user://player_save.json`
- load() 方法：反序列化，首次启动创建默认存档
- 自动存档时机：关卡完成时、购买物品后、任务状态变更时
- 手动存档按钮（主菜单设置面板中）

### Out of Scope

- 不做云存档同步（原因：离线单机；重开触发：后端需求）
- 不做多存档槽（原因：首期单槽；重开触发：需求 PRD）
- 不做存档加密（原因：本地单机数据；重开触发：安全需求）
- 不做存档迁移（原因：首期无历史版本；重开触发：版本升级需求）

### 待确认问题与延期项（Open Questions & Deferred）

**Must-Confirm**

- OQ-001：存档文件格式 → 结论：JSON，字段自描述，便于调试
- OQ-002：首次启动行为 → 结论：调用 load()，文件不存在则创建默认空存档（level=1, stars=0, inventory={}, missions={}）

**Deferred**

- DEF-001：存档版本号（save_format_version）→ 后续加字段，支持版本迁移

## 验收标准

- [ ] **AC-1**：PlayerData.save() 将当前状态正确写入 `user://player_save.json`
  - **反例（本 AC 排除）**：文件不存在或 JSON 格式错误
- [ ] **AC-2**：PlayerData.load() 从 `user://player_save.json` 正确恢复所有字段
  - **反例（本 AC 排除）**：字段值为默认值（未恢复）
- [ ] **AC-3**：首次启动（无存档文件）时，load() 创建默认空存档并返回成功
  - **反例（本 AC 排除）**：load() 返回错误或文件仍不存在
- [ ] **AC-4**：PlayerData 作为 Autoload 可在任意脚本中通过 `$PlayerData` 访问
  - **反例（本 AC 排除）**：访问时报 null 或节点未找到
- [ ] **AC-5**：关卡完成后自动触发 save()，存档文件 timestamp 更新
  - **反例（本 AC 排除）**：关卡完成后存档未写入
