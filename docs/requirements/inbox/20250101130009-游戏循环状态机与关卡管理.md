# 20250101130009-游戏循环状态机与关卡管理

# Gate-0 澄清与范围

## 原始诉求（verbatim，禁止改写）

> 实现游戏主循环状态机：管理 Main Menu → Playing → Paused → LevelClear → GameOver → NextLevel 的完整状态流转；实现球体回收/丢失逻辑和关卡切换逻辑。

## 歧义登记

歧义登记: none（已逐句复核，触达面：游戏循环状态机；确认人:Agnes；日期:2025-01-01）

## 业务目标

串联 R01~R08 所有子系统，形成完整可玩的游戏流程：玩家可以从主菜单开始游戏、完成关卡、面对失败、继续或返回。

## 用例 / 用户故事

1. 作为玩家，我能从主菜单开始游戏并看到当前关卡的方块布局
2. 作为玩家，球体掉出屏幕底部后我失去一条生命，生命耗尽后看到 Game Over 画面
3. 作为玩家，消除所有方块后看到关卡完成提示，可以进入下一关
4. 作为玩家，我可以暂停游戏并恢复

## 范围与切片

> 背景：`game.gd` 已有 score/lives/missiles 变量和 `_init_game()` / `_game_over()` 方法，但状态机不完整。
> In Scope 只写能力边界。

### In Scope（本期交付）

- 游戏状态枚举：`STATE_MENU`, `STATE_PLAYING`, `STATE_PAUSED`, `STATE_LEVEL_CLEAR`, `STATE_GAME_OVER`
- `game.gd` 完整状态机实现：
  - `_start_level(level_index)`：加载关卡、实例化方块、重置球和 Pad
  - `_on_ball_lost()`：球出界后扣生命，lives <= 0 时进入 Game Over
  - `_on_level_clear()`：所有方块消除后进入 Level Clear 状态
  - `_on_game_over()`：播放 Game Over 动画/场景，保存进度
  - `_next_level()`：加载下一关卡 JSON
  - `_return_to_menu()`：返回主菜单并保存数据
- 球体出界检测：Ball 触碰底部边界时 emit `ball_lost` 信号
- 关卡切换：通过 LevelLoader 加载下一个 level_XXX.json
- 暂停功能完善：现有 tap_pause 绑定接入状态机

### Out of Scope

- 不做关卡选择菜单（原因：首期线性流程；重开触发：关卡 >10 后）
- 不做关卡难度动态调整（原因：首期硬编码；重开触发：平衡性需求）
- 不做暂停时的冻结物理（原因：首期简化；重开触发：需求 PRD）
- 不做关卡完成动画（原因：首期简化；重开触发：R11 特效系统完成后）

### 待确认问题与延期项（Open Questions & Deferred）

**Must-Confirm**

- OQ-001：球出界判定 → 结论：Ball position.y > viewport_height + ball_radius 时判定为出界
- OQ-002：关卡完成条件 → 结论：World 节点下 Block 子节点数量 == 0 时触发
- OQ-003：Game Over 后的数据处理 → 结论：保存当前关卡进度（max_level_unlocked 不递增），stars 保留

**Deferred**

- DEF-001：关卡选择/跳过功能 → 后续版本
- DEF-002：暂停时冻结所有实体移动 → 后续版本

- [ ] **AC-3**：Ball 出界后 emit `ball_lost` 信号，game.gd 收到后 lives -= 1 并更新 HUD

- [ ] **AC-4**：lives <= 0 时进入 Game Over 状态并保存存档（不递增 max_level_unlocked）

- [ ] **AC-6**：`_next_level()` 加载下一关卡（level_index + 1），文件不存在时回到主菜单
