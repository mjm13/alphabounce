# 20260101130017-画面动画对等规格

# Gate-0 澄清与范围

## 原始诉求（verbatim，禁止改写）

> 定义安卓重构版在布局、特效、反馈、动画上与原版对等的验收规格，使「同样画面」可量化判定。

## 歧义登记

歧义登记: none（已逐句复核，触达面：视觉规格；确认人:Agnes；日期:2026-08-28）

## 业务目标

建立可量化的画面/动画对等验收基线，覆盖 UI 布局、消除/击中特效、敌人/方块动画、背景与反馈。

## 用例 / 用户故事

1. 作为测试者，我能逐项比对真机截图与原版，判定布局/精灵是否一致
2. 作为玩家，消除方块/击中敌人/发射导弹的特效与原版一致
3. 作为玩家，敌人移动、方块破碎、球拖尾等动画与原版一致

## 范围与切片

> 背景：依赖 R15（资源）、R13（粒子）、R14（UI）。原版视觉行为来自 Pixi 渲染层与 `fx/` 特效模块。
> In Scope 只写能力边界（规格定义 + 轻量实现）。

### In Scope（本期交付）

- **布局规格**：主菜单/游戏 HUD/任务面板/商店面板的元素位置、尺寸、配色对照原版，产出《画面布局对照表》（R14 引用）
- **特效规格**：方块消除、方块破碎、敌人消灭、球-块碰撞火花、Pad 发射、导弹发射等的粒子表现对照原版（`fx/` 模块）→ 驱动 R13
- **动画规格**：Dragon 横扫拖光、Drone 变形、Generator 生成 Molecule、GUARDIAN 受击、球拖尾等动画曲线/时长对照原版 → 驱动 R08/R13
- **反馈规格**：得分飘字、生命增减、关卡切换转场、屏幕震动（如 Ouverture 挤压）对照原版
- **真机比对方法**：定义截图比对清单（关键场景：主菜单/游戏中/任务/商店/GameOver），作为 R14/R15 的 Gate-2 证据

### Out of Scope

- 不重新设计美术（资源缺失替代策略由 R15/R18 决议，不在此定义新美术）
- 不做性能优化（规格不约束帧率，仅约束表现一致）

### 待确认问题与延期项（Open Questions & Deferred）

**Must-Confirm**

- OQ-001：比对基准 → 结论：以原版运行截图或 `docs/requirements/assets_map.md` 资源为准
- OQ-002：分辨率适配 → 结论：保持原版逻辑比例，Android 多分辨率等比缩放（黑边或安全区），不拉伸变形

```bash

# 2 USB 安装 + 启动
adb -s <DEVICE_SERIAL> install -r game/bin/AlphaBounce_debug.apk
adb shell am start -n com.eternaltwin.alphabounce/com.godot.game.GodotAppLauncher
# 3 在 DebugLauncher 中点选 R18 进入本需求验收入口
# 4 AC 断言日志（须全部 PASS）
adb logcat -d | grep "R18_AC"
# 5 截图取证（主菜单/游戏中/任务/商店/GameOver 五个关键场景各一张）
```
