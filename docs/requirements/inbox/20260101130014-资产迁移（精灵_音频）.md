# 20260101130014-资产迁移（精灵/音频）

# Gate-0 澄清与范围

## 原始诉求（verbatim，禁止改写）

> 将 AlphaBounce 原版 Haxe/Pixi 源码中的全部美术与音频资源迁移到 Godot 工程，建立命名映射，使安卓重构版的画面与音效与原版一致。

## 歧义登记

歧义登记: none（已逐句复核，触达面：资产管线；确认人:Agnes；日期:2026-08-28）

## 业务目标

提供与原版像素级/等效一致的精灵图与音频，作为「同样画面/音效」的物理基础，使 R12/R13/R14/R18 具备可对标素材。

## 用例 / 用户故事

1. 作为开发者，我能从原版 `frontend/src/static/images/` 与音频目录取得全部角色/方块/UI/背景精灵与音效/BGM
2. 作为开发者，Godot 工程中资源命名与原版保持一致或建立可追溯映射，便于后续需求引用
3. 作为玩家，安卓版画面与音效与原版无差异

## 范围与切片

> 背景：原版资源在 `D:\Project\Self\EternalTwin-Alphabounce\frontend\src\static\images\`（精灵图集/序列帧文件夹）与音频目录。Godot 资源应置于 `game/resources/images/`、`game/resources/audio/`。
> In Scope 只写能力边界。

### In Scope（本期交付）

- 资源盘点：遍历原版 `images/`、`sounds/`、`music/`（或等同目录），产出《原版资源清单》（文件名→用途→尺寸/帧数/格式）
- 精灵迁移：将原版 PNG/图集/序列帧导入 `game/resources/images/`，保持原尺寸与帧结构；图集须用 `AtlasTexture` 或 `SpriteFrames` 还原切分
- 音频迁移：将原版音效/音乐导入 `game/resources/audio/`，格式转码为 Godot 友好格式（ogg/wav），命名映射表保留原文件名
- 命名映射表：`assets_map.md` 记录 原版路径 ↔ Godot 路径 ↔ 用途（球/Pad/方块×N/敌人×11/Molecule×7/GUARDIAN/背景/UI/音效×M/BGM×K）
- 缺失标注：原版未提供或无法识别的资源，在映射表标注 `[缺失]`，由 R18 决定替代策略

### Out of Scope

- 不重绘/再创作美术资源（除非映射表标注 `[缺失]` 且 R18 决议替代）
- 不调整资源版权/许可（沿用原版 EternalTwin 许可）
- 不做资源压缩优化（保留原质量，性能优化属后续需求）

- OQ-002：图集切分方式 → 结论：保留原图集元数据（若有 `.json`/`.xml` 描述）用 `SpriteFrames`/AtlasTexture 还原

```bash
# 1 构建本需求独立 debug 包
godot --path game --headless --export-debug "Android" game/bin/AlphaBounce_debug.apk
# 2 USB 安装 + 启动
adb -s <DEVICE_SERIAL> install -r game/bin/AlphaBounce_debug.apk
adb shell am start -n com.eternaltwin.alphabounce/com.godot.game.GodotAppLauncher
# 3 在 DebugLauncher 中点选 R15 进入本需求验收入口
# 4 AC 断言日志（须全部 PASS）
adb logcat -d | grep "R15_AC"
# 5 截图取证
adb shell screencap -p /sdcard/R15.png && adb pull /sdcard/R15.png docs/evidence/R15.png
```
