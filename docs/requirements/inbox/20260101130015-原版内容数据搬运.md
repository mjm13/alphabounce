# 20260101130015-原版内容数据搬运

# Gate-0 澄清与范围

## 原始诉求（verbatim，禁止改写）

> 将 AlphaBounce 原版 Haxe/Pixi 源码中的关卡数据、任务数据、商店数据、敌人定义、方块类型定义等原始内容，搬运为 Godot 工程可用的 JSON/资源配置，数值与行为与原版一致。

## 歧义登记

歧义登记: none（已逐句复核，触达面：数据层；确认人:Agnes；日期:2026-08-28）

## 业务目标

以原版为唯一事实源，建立 Godot 侧可被各系统加载的内容数据，确保「同样任务/关卡/敌人」。

## 用例 / 用户故事

1. 作为开发者，我能从原版 `Level.hx`/`MissionInfo`/`ShopManager`/`Block.hx`/`ev/`/`el/Molecule.hx` 提取结构化数据
2. 作为开发者，关卡/任务/商店/敌人配置以 JSON/资源形式存在于 `game/resources/data/`，数值对齐原版
3. 作为玩家，游戏内关卡布局、任务目标、商店商品与原版一致

## 范围与切片

> 背景：原版数据层在 `common/src/`（前后端共享）与 `frontend/src/haxe/`（Block.hx、ev/*、el/Molecule.hx、Level.hx）。Godot 侧落点 `game/resources/data/`。
> In Scope 只写能力边界。

### In Scope（本期交付）

- **关卡数据**：提取原版关卡网格尺寸、方块布局、敌人配置、目标条件 → `game/resources/data/levels/level_xxx.json`（字段对齐 ADR-002 / `Level.hx`）
- **方块类型全量**：提取 `Block.hx` 全部方块类型常量（普通/钢铁/Bonus/DRAGON/MISSILE/MINE/INSECT/KILL/GUARDIAN/GENERATOR/CAGE/REDUC/GLUE 等）的属性（HP、颜色、行为）→ `game/resources/data/blocks.json`
- **敌人定义**：提取 11 种 ev 敌人（Dragon/Drone/Generator/Indigestion/Javelot/Ouverture/Quasar/Storm/UltraViolet/Unification/Wave）行为参数 + 7 种 Molecule（飞行怪物）属性 + GUARDIAN(Boss) 击杀条件 → `game/resources/data/enemies.json`
- **任务数据**：提取原版任务类型/奖励/完成条件 → `game/resources/data/missions.json`
- **商店数据**：提取原版商品/兑换货币/价格（DRONE_PERFO/DRONE_SPEED/DRONE_CONVERTER/DRONE_COLLECTOR 等升级项）→ `game/resources/data/shop.json`
- **存档字段**：提取原版存档字段（关卡、物品、分数、解锁）→ `game/resources/data/save_schema.json`

### Out of Scope

- 不做数据平衡性调整（数值须严格对齐原版）
- 不做新增关卡/任务（超出原版范围，除非用户后续要求）

## 真机独立验收（USB 调试模式 · 强制）

> 标准来源：`docs/requirements/execution-plan.md` §真机独立验收标准（USB 调试模式）。
> 原则：**不依赖任何未完成的上游需求，独立构建 debug 包并在 USB 真机上验收**。
> 注：R16 是 R02/R05/R06/R07/R08/R11 的数据源头。其产出的 **schema 即 `game/debug/fixtures/` 各 mock 的字段契约**——任何 mock 必须与 R16 正式 schema 同构，以便下游需求在 R16 完成后仅换数据源即可重跑。

| 项 | 内容 |
|---|---|
| 验收入口（debug 场景） | `game/debug/R16_data_debug.tscn` |
| 入口注册 | `DebugLauncher`（`game/debug/debug_launcher.tscn`）菜单项 `R16 原版内容数据搬运` |
| 依赖解耦 / Mock 基线 | 无（本需求即正式数据生产者；debug 场景负责在真机上 `JSON.parse` 全部产出文件并断言字段完整） |
| 验收类型 | 真机断言 + 加载（JSON 可解析 + 字段齐全 + 能被下游 loader 消费） |

**验收步骤（可复跑）**

```bash
# 1 构建本需求独立 debug 包
godot --path game --headless --export-debug "Android" game/bin/AlphaBounce_debug.apk
# 2 USB 安装 + 启动
adb -s <DEVICE_SERIAL> install -r game/bin/AlphaBounce_debug.apk
adb shell am start -n com.eternaltwin.alphabounce/com.godot.game.GodotAppLauncher
# 3 在 DebugLauncher 中点选 R16 进入本需求验收入口
# 4 AC 断言日志（须全部 PASS）
adb logcat -d | grep "R16_AC"
# 5 截图取证
adb shell screencap -p /sdcard/R16.png && adb pull /sdcard/R16.png docs/evidence/R16.png
# 6 日志门禁：零 Godot ERROR / SCRIPT ERROR
adb logcat -d -v brief | grep -iE "godot|script error"
```

**AC 自检映射**：debug 场景对 `levels/`、`blocks.json`、`enemies.json`、`missions.json`、`shop.json`、`save_schema.json` 逐个 `JSON.parse()` 并打印 `R16_AC-n PASS/FAIL`，与 AC-1..AC-4 一一对应；Gate-2 证据须含 `docs/evidence/R16.png` + 全部 AC PASS 的 logcat 片段 + 零 ERROR 结论。**量化门槛**：须打印关卡总数与敌人类型计数行（`R16_AC-1_LEVELS=<N>`、`R16_AC-3_ENEMIES=11ev+7mol+GUARDIAN`），作为「完全对标」的量化终点。
