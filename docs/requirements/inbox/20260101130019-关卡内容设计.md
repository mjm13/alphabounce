# 20260101130019-关卡内容设计（自建关卡集）

# Gate-0 澄清与范围

## 原始诉求（verbatim，禁止改写）

> 原版关卡数据不可搬运（UGC + 服务端 + 编解码 FIXME）。按原版 `Level.hx` 字段结构 + `Block.hx` 方块类型表，手工设计一套安卓版首发关卡集 JSON，作为 R02 LevelLoader 与 R10 关卡管理的数据源。

## 歧义登记

歧义登记: none（已逐句复核；确认人:meijianming；日期:2026-08-29）

## 业务目标

提供与原版网格/方块体系一致的、可玩的首发关卡内容，使安卓版有完整可通关链路，不依赖服务端。

## 用例 / 用户故事

1. 作为玩家，我能从选关列表进入逐个关卡，关卡含合法的球-块布局与目标。
2. 作为开发者，LevelLoader 从本需求产出的 JSON 加载关卡，无需联网。

## 范围与切片

### In Scope（本期交付）

- **关卡 schema**：对齐原版 `Level.hx`（`Cs.hx` 网格 14 列 × 23 行，格子 28×14），字段含 `grid`（方块类型二维数组）、`goal`（目标类型）、`name`、`seed`
- **首发关卡集**：手工设计 **N 个关卡**（建议 12–24 个，覆盖教学→进阶→GUARDIAN Boss 关），难度曲线递增
- **目标类型**：对齐原版（消除全部方块 / 达指定分数 / 击杀 GUARDIAN），在 schema 中定义
- **校验脚本**：`game/debug/fixtures/validate_levels.gd` 或等价，构建期校验 JSON 可解析、网格尺寸合法、方块类型在 `Block.hx` 枚举内

### Out of Scope

- 大地图星球的地理分布（navi 已排除，见 PRD Out of Scope）
- 关卡编辑器（navi/menu/Editor 已排除）
- 联网拉取服务端关卡（离线单机）

### 待确认问题与延期项

- OQ-001：首发关卡数 N → 结论：建议 **16 个**（4 星球 × 4 关，末关含 GUARDIAN）
- OQ-002：关卡文件落点 → 结论：`game/debug/fixtures/levels.json`，R16 完成后正式数据同路径替换
- OQ-003：GUARDIAN 关是否必须 → 结论：是，至少一个含 `GUARDIAN=55` 方块，验证 R11 导弹击杀链路

# Gate-1 方案与验收

## 验收标准（真机独立，强制）

- [ ] **AC-1**：`levels.json` 可被 `ResourceLoader`/JSON 解析，字段对齐 `Level.hx`
  - 反例：JSON 语法错误或字段缺失
- [ ] **AC-2**：每个关卡 `grid` 为 14×23，方块类型 id 均在 `Block.hx` 枚举（1–56 已知集合）内
  - 反例：尺寸不符或非法类型
- [ ] **AC-3**：至少 1 个关卡含 `GUARDIAN` 方块，至少 1 个关卡目标为「击杀 GUARDIAN」
  - 反例：无 GUARDIAN 关
- [ ] **AC-4**：真机经 DebugLauncher 进入关卡预览场景，渲染首关布局，零 ERROR
  - 反例：加载失败或报错
- [ ] **AC-5**：首发关卡数 ≥ 12，难度曲线递增（按方块密度/敌人数）

## 实现方案

- 关卡 JSON 结构（草案）：

```json
{
  "levels": [
    {
      "id": "L01",
      "name": "新手村",
      "goal": "clear",
      "seed": 12345,
      "grid": [[13,0,...],[...]]   // 14×23，值=Block.hx 类型 id
    }
  ]
}
```

- 校验：headless 下加载 JSON，断言维度与类型，打印 `LEVEL_AC-n PASS`
