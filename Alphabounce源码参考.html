② 构建 / 运行方式

原版（难以独立构建）

# 构建命令（来自 Makefile）
haxe prod.hxml
cp swf/client.swf ../web/www/swf/game.swf

# prod.hxml 关键参数
-swf swf/client.swf
-swf-lib swf/gfx.swf   # 依赖美术库
-main Manager
-cp src -cp ../com
-swf-version 8 --flash-strict
-D prod
-cmd swfmake          # 需外部 swfmake 工具

依赖外部 mt Haxe 库与 swfmake 命令（不在仓库内）；产物是 Flash SWF，需旧版 Flash Player / Ruffle 才能运行；不含服务端代码。

重写（现代可一键运行）

# 本地环境
haxelib install haxelib.json --always
yarn install --immutable
yarn run start        # 构建+启动服务

# 或用容器（需 Redis）
docker compose --file ./compose.yaml up --build
# 镜像：registry.gitlab.com/
#   eternaltwin/alphabounce/alphabounce:latest

技术栈：Haxe 4.3.7 + Node 24 + Yarn + Redis；渲染用 PixiJS；构建由 build.hxml + Node 脚本编排，浏览器直接可玩。

③ 实现差异对照

维度原版 Motion TwinEternal-Twin 重写
语言Haxe（编译为 AVM1/SWF）Haxe + TypeScript/Node
渲染Adobe Flash / MovieClipPixiJS（WebGL/Canvas）
服务端无（仅客户端+数据定义）完整 Node 后端（REST API + HTML）
数据库—Redis
部署Flash SWF（已淘汰）Docker/OCI 容器，浏览器直跑
许可证存档，未明示开源协议AGPL-3.0-or-later
网络协议com/Protocol.hx 定义请求/响应枚举REST API（backend 重写）
代码组织client/src 单块 + com 共享common/backend/frontend 三层分离
状态2007 年发布，已停更开发中（TODOLIST 列有落地崩溃等 bug）

④ 建议阅读入口

原版

  • client/src/Manager.hx — 主入口、场景/菜单切换
  • client/src/Game.hx、Block.hx、Bouncer.hx — 核心玩法
  • com/Protocol.hx — 网络协议与玩家数据结构
  • com/ZoneInfo.hx、MissionInfo.hx — 关卡/任务数据

重写

  • README.md — 环境/构建/部署总览
  • frontend/src/ — 浏览器游戏逻辑（对照原版 Game/Block）
  • backend/src/ — 服务端 API（替代原版 Protocol）
  • common/src/ — 共享类型/逻辑
  • TODOLIST.md — 当前未完成项，定位改造点
一句话总结：原版是「Haxe 写、Flash 跑、只有客户端」的历史源码；Eternal-Twin 是「同样用 Haxe、但加了 Node 后端 + Redis + PixiJS 渲染、AGPL 开源、浏览器可玩」的现代重写。研究玩法逻辑看原版 client/src，要改造/运行看重写版。
