# 注释格式与维度（comment-format）

写/改核心业务注释时**必须** Read 本文件。与具体语言、框架无关；栈示例仅说明结构。

## 方法分层与维度（不可混用）

| 层级 | 适用 | 必填维度 | 可选维度 |
| --- | --- | --- | --- |
| **端点层** | 对外暴露的入口 | `[接口地址]` `[功能描述]` `[业务逻辑]` | `[业务菜单]` `[前端路径]` `[涉及数据表]` `[涉及外部模块]` `[修改记录]` |
| **内部层** | 内部业务处理、工具、Helper、复杂私有方法 | `[核心目的]` `[业务逻辑]` | `[涉及数据表]` `[涉及外部模块]` `[修改记录]` |

端点写 `[接口地址]`/`[功能描述]`；内部写 `[核心目的]`。同一段注释勿同时出现端点维与 `[核心目的]`。

## 维度定义

| 维度 | 含义 |
| --- | --- |
| `[接口地址]` | 入口标识：HTTP 路径、命令名、消息主题、公开函数签名等 |
| `[功能描述]` | 该入口对外完成的业务目标 |
| `[核心目的]` | 该内部方法解决的业务问题 |
| `[业务逻辑]` | 核心业务步骤；写「做什么 / 为什么」，勿泛化模板句 |
| `[涉及数据表]` | 持久化/状态资源，标注 `(R/W/D)` |
| `[涉及外部模块]` | 外部服务/组件名 |
| `[业务菜单]` | 仅有前端界面时填 |
| `[前端路径]` | 仅有前端工程时填 |
| `[修改记录]` | 逻辑变更时追加 |

## 核心原则

1. **语义优先**：`[业务逻辑]` 与方法体逐步对应，不复述代码。
2. **高层总结底层**：端点 `[业务逻辑]` 提炼所调内部方法含义；勿写空壳「调用某某服务」。
3. **自下而上**：批量先底层再高层。
4. **证据驱动**：无证据则省略可选维；勿写 `TODO: 待确认` 或 `[涉及数据表]: 无`。
5. **只改注释不改逻辑**；保留原有有效业务背景。

## [业务菜单] / [前端路径] 取证

顺序固定：先文件后菜单。

```text
入口标识 → 查前端调用 → 定位前端页面文件 → [前端路径]
        → 该文件对应路由 → 菜单 → [业务菜单]
```

找不到菜单时只上溯一层；仍无则省略 `[业务菜单]`。勿先看菜单配置猜路径。

## 勿用的泛化 `[业务逻辑]`

- `1. 解析入参 -> 2. 执行核心逻辑 -> 3. 返回结果`
- `1. 接收请求参数 -> 2. 执行业务处理 -> 3. 返回结果`
- `1. 组装查询条件 -> 2. 执行查询 -> 3. 返回结果集`（查询方法雷同时）
- 整句仅「调用某某服务」或「封装返回」
- 格式：`[涉及数据表]: 无`、双冒号 `: :`

## 格式示例（中性）

**端点层：**

```text
注释块 {
  [业务菜单]: 一级 -> 二级 -> 三级
  [前端路径]: <页面文件>
  [接口地址]: <入口标识>
  [功能描述]: <一句话目标>
  [业务逻辑]: 1. <步骤一> -> 2. <步骤二> -> 3. <结果>
  [涉及数据表]: <资源A> (R), <资源B> (W)。
  [涉及外部模块]: <组件>。
}
```

**内部层：**

```text
注释块 {
  [核心目的]: <业务问题>
  [业务逻辑]: 1. <步骤一> -> 2. <步骤二> -> 3. <产出>
  [涉及数据表]: <资源> (R/W/D)。
}
```

## FastAPI 示例（当前栈）

```python
async def list_users(...):
    """[业务菜单] 系统管理 -> 用户管理
    [前端路径] frontend/src/views/system/SystemUsersView.vue
    [接口地址] GET /api/system/users
    [功能描述] 用户分页列表
    [业务逻辑] 1. 校验 system:user:view -> 2. PageResult 返回
    [涉及数据表] sys_user (R)
    """
```

## Java 示例（仅结构说明，不构成基线约束）

```java
/**
 * [业务菜单] 资源管理
 * [前端路径] frontend/src/views/resource/ResourceTreeView.vue
 * [接口地址] GET /api/resources/tree
 * [功能描述] 资源维护树
 * [业务逻辑] 1. 读取 resource 建树 -> 2. 返回维护树
 * [涉及数据表] resource (R)
 */
@GetMapping("/tree")
public Result<List<MenuTreeNode>> tree() { ... }
```

## 本项目纳入范围（栈约定；rules 不重复）

| 层 | Glob | 校验要点 |
| --- | --- | --- |
| 端点层 | `backend/**/*_router.py` | 端点 docstring：`[接口地址]` / `[功能描述]` / `[业务逻辑]`（及 UI 映射维） |
| 内部层 | `backend/**/*_service.py`、`*_admin_service.py` | public 方法：`[核心目的]` / `[业务逻辑]` |
| 前端 API 映射证据 | `frontend/src/api/*.ts` | 已映射端点补 `[前端路径]` / `[业务菜单]` |

`pipeline_guard.py --check-comment-sync` 按上表校验；上表为路径约定的 SSOT。
